# Работа с ИИ

**Инструмент:** Codex, ассистент на базе GPT-6. Использован для разбора PDF, написания
кода, тестов и документации, запуска проверок. Источник бизнес-требований —
`Тестовое_Junior_Python_FastAPI.pdf`.

## Ключевые запросы

Ниже смысл реальных запросов пользователя, отредактированный для читаемости:

1. «Посмотри выданное тестовое задание Junior Python / FastAPI» — был передан путь
   к PDF. Ассистент прочитал документ и выделил требования к деньгам, рассрочке,
   идемпотентности, статусам, тестам и сдаче.
2. «Реализуй задание с PostgreSQL, передавай запросы через Redis, раздели приложение
   на сервисы и заверни в Docker. Добавь CI с запуском всех тестов» — к требованиям
   PDF добавились инфраструктура и разделение обработки.
3. «Сделай AI_LOG.md с грамотно оформленными моими запросами и читаемый код, в котором
   я смогу разобраться. Остальное — как в тестовом» — поэтому функции бизнес-логики
   выделены отдельно, а в README добавлен порядок чтения файлов.

## Слабые предложения и проверка

Первая предложенная ассистентом схема оставляла запись платежей и проверку статусов
в API, а Redis использовала для фоновых событий. При сверке с пожеланием передавать
обработку через Redis стало видно, что этого недостаточно. Итоговая схема передаёт
все бизнес-команды worker через Redis и возвращает результат по тому же каналу.
Синхронное ожидание сохраняет требуемые HTTP-коды `201`, `200`, `404` и `409`.

В описании сервисов дважды упоминалась БД и отдельно — ответ. Ассистент явно указал
принятое допущение: четыре контейнера (`api`, `worker`, `redis`, `postgres`), одна БД,
ответ клиенту отдаёт API. Две PostgreSQL не добавлялись без определённых ролей.

Первый запуск pytest выявил ошибку в зависимостях ассистента: был указан обычный
`sqlalchemy`, а установленная версия для async-модуля требовала `greenlet`.
Это обнаружилось по `ImportError` при загрузке тестов. Зависимость исправлена на
`sqlalchemy[asyncio]`, lock-файл обновлён. Сборка образа сама по себе такую ошибку
не обнаружила, поэтому проверяется и фактический запуск приложения.

**Выполненные проверки:** все 88 тестов прошли локально и в Docker с настоящими
PostgreSQL и Redis. Проверены суммы и ответы, все переходы статусов, гонки двух worker,
повтор после коммита БД, восстановление команды после сбоя consumer и HMAC.
Ruff и проверка форматирования прошли, четыре контейнера запущены и имеют статус
`healthy`. Через HTTP проверены тарифы, создание платежа, рассрочка, промокод,
идемпотентность, вебхуки и `404`. GitHub Actions настроен; запуск на GitHub произойдёт
после push. Действия и замечания пользователя не выдумывались.
