# Как я работала с ИИ

Использовала Codex на базе GPT-6. Передала PDF с заданием, затем уточняла стек,
архитектуру и удобство запуска. Ниже — короткий пересказ моих реальных запросов,
а не дословная переписка. В начале дважды останавливала работу, чтобы уточнить задачу.

## Что я просила

1. Разобрать тестовое на FastAPI и реализовать требования из PDF.
2. Использовать PostgreSQL, передавать команды и ответы через Redis, вынести
   алгоритм в отдельный обработчик и собрать всё в Docker. Описание сервисов
   уточнялось; итог — API, worker, Redis и одна PostgreSQL.
3. Добавить CI со всеми тестами, понятный код и AI_LOG с историей работы.
4. Объяснить, готов ли проект к сдаче и что подтверждает зелёный CI; добавить CD
   и объяснить выбор Debian для контейнера и Ubuntu для CI.
5. Добавить requirements и разобрать, на какие баллы по критериям задания можно
   претендовать. Оценку в 100 баллов проверяющий пока не выставлял.
6. Описать запуск без Docker и быстрые тесты для ручной проверки.
7. Объяснить переменные публикации в GHCR и выяснить, почему CD не запускается.
8. Исправить и запустить CI, коротко оформить эту историю от моего лица и объяснить,
   как пользоваться проектом и проверками.
9. Объяснить скриншот Actions: почему `checks` зелёный, а публикация образа пропущена.
   Причина — запуск из `develop`, тогда как публикация настроена на push в `main`.
10. Слить `develop` в `main` и проверить, можно ли сдавать проект: сверить требования
    задания, дождаться CI в основной ветке и проверить публикацию Docker-образа.

## Где предложения пришлось исправить

Сначала Redis предлагалось использовать только для фоновых событий. Это не совпало
с моим пожеланием: в итоге через него проходят и команды, и результаты обработки.

В зависимостях ИИ указал обычный SQLAlchemy. Первый запуск тестов показал `ImportError`
из-за отсутствующего `greenlet`; зависимость исправили на `sqlalchemy[asyncio]`.
Позже GitHub CI поймал пробелы на пустой строке в `app/service.py` — Ruff их убрал.

Проверки запускал ассистент: Ruff, форматирование, actionlint и 88 тестовых сценариев
прошли. Тесты проверены с настоящими PostgreSQL и Redis, в Docker и после установки
через pip. Отдельно проверены HTTP-запросы через четыре работающих контейнера.

## Как пользоваться

Для запуска и тестов есть команды в [README](README.md). CI запускается после push
или открытия PR; публикация образа в GHCR — после успешного CI при push в `main`.
Автодеплой на сервер пока не настроен. В `develop` публикация пропускается.

Для следующей доработки удобно передать ИИ конкретный сценарий, ожидаемый результат
и ошибку из лога, затем проверить предложенные изменения тестами и разобраться в коде.
